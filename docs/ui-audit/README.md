# 界面审查报告（只读）

对一个真实运行中的实例做**只读**界面审查，只查三类问题：

1. **按钮无效** —— 渲染了却点不动、点了没反应、点了触发别的功能
2. **PC 端 / 移动端界面显示不正常** —— 溢出、被裁、重叠、遮挡、跑出视口
3. **字体错乱或重复性显示** —— 乱码、字号异常、同一文案重复渲染

不含性能、安全、文案质量、接口语义，**不修改任何代码**。

## 这段报告是怎么来的

四个分组审查员分别负责一块页面，各自用 CDP 驱动 headless Chrome 在 **桌面 1440×900** 与 **移动 390×844（DPR 2）** 两个视口下量测；之后由汇总复核员用独立自建探针**逐条复核**（`Page.captureScreenshot` + `Runtime.evaluate` 量测 + `Input.dispatchMouseEvent` 真实命中点击），上游 25 条全部复核、抽样复现率 100%，其中 3 条被推翻/降级、2 条未复现、6 条同根因合并，最终确认 16 条。

## 脱敏说明

原始报告写于一台内网机器上，里面的实例地址、代理地址、本机绝对路径都已替换为占位符，原文的截图与量测 JSON **未随报告入库**（合计数百 MB）。阅读时按下表还原语义：

| 占位符 | 含义 |
|---|---|
| `<instance>` / `http://<instance>:6680` | 被测实例的主机与端口 |
| `<proxy>` / `<proxy-host>` | 上游代理地址 |
| `<container-ip>` | 容器视角下的来源 IP |
| `<audit-root>/` | 审查产物（截图、量测 JSON）所在的本地目录 |

每条缺陷的「证据」列都给了具体的**数值**（坐标、宽高、字号、`scrollWidth`/`clientWidth`、覆盖率等），这些数值本身就是判据，不依赖截图也能核对；截图只是旁证。

四个分报告的「证据目录」「复现命令」小节里引用的 `<audit-root>/...` 是当时逐个问题现写的一次性探针（`jmfab2.mjs`、`jmhistrow.mjs` 等），**没有入库**；要重新取证统一用 [`scripts/ui-audit.mjs`](../../scripts/ui-audit.mjs)，它对同一类问题给出同样的字段。

## 复现方式

```bash
# 桌面视口
NAV_BASE=http://127.0.0.1:3000 \
NAV_COOKIE=<nowen 会话 cookie 的值> \
node scripts/ui-audit.mjs /books 1440 900 4000 books

# 移动视口
NAV_BASE=http://127.0.0.1:3000 \
NAV_COOKIE=<nowen 会话 cookie 的值> \
node scripts/ui-audit.mjs /jm 390 844 4000 jm-mobile
```

脚本输出一段 JSON（溢出、裂图、死链接、乱码、过小字号、被裁切、相邻重复文本、固定层是否出屏）并落两张截图。`NAV_JM_TOKEN` / `NAV_JM_USER` 是可选的，只有审查 JM 模块内需要登录态的页面时才要带上。

## 结论提醒

16 条里两条「高」值得优先看：**R-01** 阅读器浮动按钮被底栏 100% 覆盖（三个阅读器同根因，点「Translate Page」实际触发夜间模式）和 **R-03** 多选态「加载更多」被批操作条压 63%（点中心无反应、点顶边才生效）。这两条都不是「按钮没绑事件」，而是**元素被盖住**——所以死按钮普查（301 个可点元素 `dead=0`）发现不了它们。
